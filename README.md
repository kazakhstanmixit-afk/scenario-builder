# Конструктор рекламных сценариев

Небольшой веб-инструмент: вводишь товар и описание — разные ИИ-модели (через
OpenRouter: Claude, GPT, Gemini, Grok или любые другие) предлагают варианты
заголовков, текстовых и визуальных хуков, идей демонстрации товара, связок
«до/после» и общего сценария подачи. Понравившиеся варианты от разных моделей
можно собрать в один финальный сценарий, отредактировать и скачать.

## Как это устроено

- `server.js` — Express-сервер: отдаёт фронтенд и API.
- `openrouter.js` — обращение к OpenRouter API и парсинг ответов моделей.
- `db.js` — простое хранение проектов в файле `data/projects.json`.
- `public/` — фронтенд (обычные HTML/CSS/JS, без сборки).

API-ключ OpenRouter вводится в браузере (кнопка «Настройки») и хранится
только в `localStorage` этого браузера — на сервер он не сохраняется,
а передаётся с каждым запросом генерации в заголовке `x-openrouter-key`.
Получить ключ: https://openrouter.ai/keys (там же можно пополнить баланс —
у OpenRouter оплата по факту использования токенов, у части моделей есть
бесплатные лимиты).

## Запуск локально

```bash
npm install
npm start
```

Открыть http://localhost:3000, зайти в «Настройки», вставить свой
OpenRouter API-ключ.

## Деплой на Render

1. Залить этот проект в свой репозиторий на GitHub (или GitLab).
2. На render.com: **New → Web Service**, подключить репозиторий.
3. Настройки сервиса:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - Runtime: Node
4. Задеплоить. Render даст публичный URL вида `https://<имя>.onrender.com`.
5. Открыть сайт, ввести свой OpenRouter-ключ в настройках — им пользуется
   только твой браузер.

### Про хранение проектов

Проекты сохраняются в файл `data/projects.json` на диске сервера. На
бесплатном тарифе Render диск **эфемерный** — при передеплое или уходе
инстанса в сон и повторном подъёме файл может обнулиться. Для надёжного
хранения на будущее стоит:
- подключить Render Disk (постоянный диск, платный) и указать его как
  каталог `data/`, либо
- заменить `db.js` на настоящую БД (например, Render Postgres) — структура
  проекта простая (`{id, title, product, models, results, selections,
  finalText}`), переезд на БД не потребует менять фронтенд.

Пока просто помни: важные готовые сценарии лучше сразу скачивать (.txt/.md),
не полагаясь только на «Мои проекты».

## Как менять список моделей

По умолчанию используются алиасы `-latest` там, где OpenRouter их
поддерживает (чтобы не переписывать ID при выходе новых версий моделей):

- `anthropic/claude-sonnet-latest`
- `openai/gpt-latest`
- `google/gemini-pro-latest`
- `x-ai/grok-4.6` (на момент написания у Grok нет alias `-latest`)

Список редактируется прямо в интерфейсе (Настройки → добавить/убрать
модель) — новый ID модели можно взять на https://openrouter.ai/models.
Изменить дефолтный набор "из коробки" можно в `openrouter.js`
(`DEFAULT_MODELS`).

## Возможные доработки

- Экспорт в `.docx` (сейчас — `.txt`/`.md`, легко открываются и
  редактируются где угодно).
- Учётные записи, если инструментом будут пользоваться несколько человек.
- Показ прогресса по каждой модели отдельно (сейчас — один общий статус,
  пока идёт запрос ко всем моделям параллельно).
